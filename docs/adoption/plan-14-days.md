## 学习目标与止损

- 获批内容在 GitHub 和至少一个共享市场链路准确展示；合并/同步时点取决于第三方，不承诺 14 天内必成。
- 争取新增两个有证据的外部试用反馈，至少一个说明下一步人工检查是否有帮助。unknown 或运行失败同样是有效学习，不冒充成功。
- 如果下载上升而反馈不变，优先检查试用入口、目录选错和反馈门槛，不推断增长了真实用户，也不继续增加广播渠道。
- 如果曝光仍少，优先把已出现的真实故障模式写成一个可运行用例，寻求一处技术互链；不刷 Star、不互换虚假评价。
- 只有使用反馈反复证明文案或安装入口阻碍理解时才改这些资产；产品新模式、跨宿主适配和大规模重构留到独立工作。
