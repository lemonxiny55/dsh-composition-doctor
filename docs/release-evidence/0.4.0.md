## Safety and explanation limits

- Logs only contribute recognized signatures and safe candidate ids. ANSI/raw lines, arbitrary commands, URLs, paths, secrets and log-claimed runtime versions are not trusted facts or persisted log content.
- Default diagnosis performs no network call, CLI launch, plugin import or lifecycle execution; a fetch spy and executable sentinel verify these boundaries. Static parsing treats JavaScript tags as inert.
- Log files/stdin and declared patch metadata have format/size/path bounds. Sensitive environment/token/credential/workspace/chat/session paths are refused. Invalid metadata produces an incomplete/unknown result, never a health certificate.
- Profile hashes and mtimes remain unchanged after default diagnosis and exports. Export directories inside the canonical profile, symlink parents into it and linked report destinations are rejected.
- A normal update and a patched provenance chain are not independent insertions. Static duplicates remain static even when a public dump exposes only one final row. No evidence produces `unknown`; unsupported logs produce explicit `no-match` and a next step.
- Default inventory excludes home/CLI overlays, installation-level bundles and external workspace links. A locally unresolved package or absent insertion can still exist in those layers. `--composed` reuses the existing copied-profile adapter and its actual coverage/fallback.
- A DSH-family peer mismatch needs an independently selected exact host version. Host exemptions and policies are unknown; Doctor does not guess a compatible plugin release or bypass the gate.
- Prior effective values, field ownership, route/slot/hook ownership and runtime effects remain unknown. An explicit replacement fact proves replacement; a source chain proves patching. Static omitted keys do not prove runtime data loss.
