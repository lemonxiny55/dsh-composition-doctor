# 0.4.0 — Failure Explainer

**Draft for review. Do not publish until explicitly authorized.**

DSH plugin broke your setup? Composition Doctor shows which observed layer is involved and where to look next.

```sh
dsh-doctor diagnose --profile ~/.dsh/profiles/web --log dsh-error.log
```

```text
Duplicate loader entry id: session-cleaner
reported-by-log; evidence: static

session-cleaner
├── dsh.profile.bundles[0]
│   └── node_modules/session-cleaner/cordis.patch.yml
└── profile/cordis.patch.yml

Two independent insertion declarations share the same loader id.
Review both paths and keep the intended config manually.
Runtime not observed / not-run; final composition unknown.
Doctor did not modify your profile.
```

This compact diagram summarizes the CLI output from a minimized public failure case; it is not a runtime capture. [Sources and complete demos](../failure-cases.md).

New in 0.4.0:

- `diagnose`: human-first explanation, optional file/stdin log, JSON and Markdown.
- `check`: the same bounded first entry point with an explicit profile.
- Six explanations: duplicate insertions, unavailable bundles, missing/invalid patches, unmatched targets, peer/version mismatches and config replacement/override.
- Failure Explanation in the existing Web Explorer, with related graph nodes highlighted.

Read-only and offline by default. Logs are untrusted signatures, not proof of composition or runtime behavior. No automatic fix, plugin removal, upgrade, telemetry or runtime execution. A peer mismatch needs an independently selected version; a patched chain alone does not prove a whole-config replacement.

Validation details and current-release compatibility are recorded in [release evidence](../release-evidence/0.4.0.md). The current public DSH composition harness is separate from third-party runtime/UI verification. See that evidence for tests actually run and any pending CI; do not advertise pending jobs as verified.

Recording: `pnpm demo:failure` (25 seconds). Two complete public-pattern examples: duplicate insertion and missing `dsh-cad` patch. The npm release, tag and GitHub Release still require the owner's explicit authorization.
