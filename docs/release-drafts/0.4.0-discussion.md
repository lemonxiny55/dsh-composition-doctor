# Introducing Composition Doctor's Failure Explainer: which layer is involved?

**English Discussion draft for owner review; not posted.**

When a plugin breaks a DSH profile, the Web UI you would use to manage it can be unavailable too. I am preparing `dsh-composition-doctor` 0.4.0 to make that situation easier to investigate from a terminal:

```sh
dsh-doctor diagnose --profile ~/.dsh/profiles/web --log dsh-error.log
```

The command connects a supported symptom to an observed row or package, its composition source paths and a manual next step. For a bundle plus a manual insertion, the useful answer is:

```text
session-cleaner
├── bundle declaration → node_modules/session-cleaner/cordis.patch.yml
└── profile → cordis.patch.yml

Same id, two insertion declarations.
Evidence: static; final composition unknown; runtime not observed.
```

The initial patterns come from public composition/drift reports, including [#2889](https://github.com/deepseek-ai/deepseek-harness/discussions/2889), [#6539](https://github.com/deepseek-ai/deepseek-harness/discussions/6539) and the peer-gate upgrade theme in [#8199](https://github.com/deepseek-ai/deepseek-harness/discussions/8199). The regression profiles are minimized reconstructions with inert metadata, not copies of personal profiles.

This builds on the existing `why row`, `impact bundle`, snapshots, diff and upgrade preflight. The first release focuses on duplicate insertions, unavailable bundles, missing patches, unmatched targets, version contracts and config replacement. It does not guess every startup root cause.

Doctor is read-only and offline by default. It does not repair/remove/upgrade plugins, import their runtime code or upload data. Logs only identify candidate signatures; a misleading log without supporting metadata returns `unknown`. Regular patch updates are not counted as duplicate loads, and a source chain does not prove removed config keys.

The current DSH `0.2.0-rc.2` public composition contract has fresh Windows and Ubuntu 24.04 (WSL) harness checks on Node 24.19.0. Runtime/plugin UI execution remains unverified. JSON/Markdown export and the existing Web Explorer carry the same explanations and unknowns.

Repository: [lemonxiny55/dsh-composition-doctor](https://github.com/lemonxiny55/dsh-composition-doctor). This is currently an unpublished local release candidate; the public 0.3.0 package does not yet include `diagnose`. The repo includes a 25-second terminal demo and two concrete failure examples for review.

If a supported explanation helps locate your problem, the useful feedback is the first error signature and a minimized, sanitized structural reproduction—not logs containing keys, session content or workspace data. No data is collected automatically.
